# AI职场沟通训练师：完整交接

## 1. 目标与背景
用户已从学生转为职场人员。旧《AI高压沟通教练》用于株洲所新员工培训后的 AI 课程比赛，演示获第一名；新项目拟用于国变中心后续比赛，需面向实际职场、客户及国际化沟通。
目标不是让 AI 凶，而是通过合理追问训练判断意图、结论表达、组织证据和推进决策。用户最新明确要改造原 v4.18、保留 API 并接入真实模型，转交本机 Codex 实施。

## 2. 确定的产品需求
### 品牌与内容
- 产品名：AI职场沟通训练师。
- 页面不要出现“国变中心 · 比赛演示版”或比赛/内部演示标签。
- 移除毕业答辩、老师、学生身份等场景；技术交流改为技术评审专家、质量与技术专家等职业对象。
- 领导模拟围绕资源、风险、交付、决策合理追问；不能靠刻画难缠、羞辱或人格攻击制造压力，避免负面塑造领导。
- 核心场景：项目进度与决策、资源协调、技术方案评审、异常与风险、客户需求澄清、交期协调、英文需求澄清、英文进度/延期。参考 site-reference/shared/scenes.js 的8个场景。
- 英文场景英文对话、中文复盘，英文回应示范；保留扩展其他语言的空间，不必声称当前支持全部语言。

### 对象画像
- 可以查看、新建、修改自定义对象；描述称呼、角色、工作目标、关注点/判断标准、表达风格、典型原话、沟通难点和模拟边界。
- 已知事实与推断/虚拟补充明确区分，不能把模拟解读当成现实人物心理事实。
- 训练时冻结本轮对象画像及目标快照，后续编辑不能改变历史轮次含义。

### 我的沟通画像（用户特别纠正过）
- 这是显示页面，不要求用户填写自我性格/自我评分。
- AI 从长期真实沟通记录总结特征、优势、需提升方向、具体练习措施。
- 保留原话证据、来源轮次、更新时间、样本量或可信程度；样本少就谨慎表述，不能凭空定性。
- 无历史时显示尚在积累，不以填表阻止首次训练。
- 成功复盘后更新画像；画像生成失败也不能丢掉已经成功的复盘，可重试。

### 完整训练闭环
1. 选场景、对象、目标、脱敏背景和追问强度。
2. 点击开始：真实 AI 开场，直接在同一网页连续对话。
3. 对方追问可展开三层解读：表面问题、核心关切（旧版真正关心）、判断依据（旧版隐藏判断标准）。
4. 结束训练后真实 AI 对完整记录分析：总评、六维评分、逐轮点评、关键问题与调整建议、原话解读、原回答/改进示范、下轮训练计划。
5. 保存完整对话、评分依据、复盘和长期画像；可查看、再练、导出、打印/PDF。
- 用户不喜欢“复制去 ChatGPT 再录回”工作流，也不希望开始按钮因为未填个人画像不可用。
- 模型生成中禁止重复发送，保留用户已提交回应；超时/失败明白提示并可重试，不伪装成功。

## 3. 六维图与评分（最新要求）
六维固定：结论清晰、证据具体、诉求对齐、边界与风险、下一步行动、理解与协作。
- 每次完成复盘都要有六维雷达图和总评分，不能空评分条或只显示“待评”。
- 真实 AI 版需要统一评估标准、每维依据和原话证据；总分统一按六维平均取整数（避免后端5维平均、前端6维平均不一致）。
- 建议标准：0-20几乎未体现、21-40表达零散、41-60基本体现但不具体、61-80清晰且基本可执行、81-100证据/边界/行动充分且适合语境。此为实施建议，应写进模型提示词并验证，不是假称测量工具。
- 一轮短回应也可以低分，但说明样本限制；高分不能只因出现关键词。
- API 失败：允许明确标注的规则练习分兜底，不能冒充 AI 分数；成功 AI 复盘与失败/降级状态应可区分。
- 旧5维记录做兼容：保留原数据，单独标明旧评估；可重新分析完整记录生成六维，不能无依据补成 AI 分。
- 图有可读标签、0-100刻度/范围、颜色层次、手机适配和文本分数，导出也能显示。推荐无依赖 SVG，现有参考已有。
- 训练区提供可复制的虚构示例用于体验，避免将示例混入真实历史，只有用户主动提交后才成为其本轮回应。

## 4. 美学和交互
用户明确认为此前界面太紧凑、不显高级，并认为前任 HTML 比早期设计好。
已接受方向：纸色背景 #f4f1e9、深绿 #174f40、青柠 #d7ef7b；大标题、清晰字体层级、少量错位阴影和宽松留白。
- 从拥挤三列改为纵向分阶段：选择方向 → 宽幅训练 → 复盘；辅助对象关注点默认折叠。
- 训练区居中，少堆信息；首页大标题和实际场景开场预览。
- 页面不能全是文字；雷达图、数值卡片和合理摘要帮助阅读，但不要虚构用户表现。
- 保留移动端和 Windows 桌面高分辨率可用性。按钮真能操作，加载、空状态、错误完整。
- site-reference/web/style.css 最后的样式覆盖是当前最终宽松设计，前面仍有旧规则；移植时建议整理而非照搬累积覆盖。

## 5. 原项目已核实的技术基础
以 original-v4.18 为改造起点，不要直接把在线 Worker 改称本地版。
- Python server.py + 单文件 index.html（含CSS/JS）+ skills/manifest.json + 各教练 SKILL.md/references。
- start.bat / start.sh 本地启动；build_exe.bat PyInstaller 打包。旧 exe 不随包提供，不代表它会自动包含新改动；如交付 exe 必须重新构建并验证。
- 原服务器读取并拼接教练 Skill 提示词，提供配置、manifest、coach CRUD、quotes等接口。模型调用主要在前端 chatCompletion，通过 OpenAI 兼容 /chat/completions。
- 原 API 配置存 user_data/apiconfig.json，顶层 apis + active；单项包含 id/name/baseURL/apiKey/model/reviewModel/useLLM 等。
- 支持多个 API 配置、切换、测试连接、模拟模型与复盘模型。保持已有接口语义和兼容服务商，不强制改为只支持 OpenAI Responses。
- 原前端 llmReply/getReply/tryLLMReview/mergeReview/end/buildRuleReview/renderReview/exportReview 等须逐个审阅；真实模型与规则回退已共存，不能假定全程真实 AI。
- 现有 localStorage/记录/画像和数据迁移的确切实现，接手方须读代码核实；本次交接没有宣称原版已完整满足新画像需求。
- 注意敏感配置：本包配置为空，本机已有配置不得被它覆盖。保留原密钥本地可用但不打印、不提交。

## 7. 建议实施顺序与验收
先盘点源码与API链路/记录 → 制作副本 → 场景/角色与提示词 → 六维结构化复盘校验 → 画像持久化 → 移植宽松界面/图 → 测试与交付。
验收至少包括：
- 无画像可开始；中英文和客户场景都可选；角色合理追问且前后连贯。
- 多API配置仍可保存/切换/测试；完整地址归一化不破坏现有提供商。
- 一次真实模型测试覆盖开始、至少2轮、结束六维评分、三层解读、画像更新与刷新后保留；无授权凭据则报告未实测，用替身测协议，不冒充通过。
- 所有评分为0-100有效数值，总分与六维一致；缺字段/非法JSON/引用不存在/超时应处理，不能空白或随便给高分。
- API失败不丢用户原话/复盘；重试不重复记录；取消/再练不串轮。
- 画像只读，历史证据可追溯；用户配置和旧数据不丢。
- 雷达图和中文/英文标签、手机布局、导出、打印实际可读。
- 原5维历史记录兼容；没有比赛标签、学生内容和人格羞辱。
- README写清本地启动与API配置，CHANGELOG记录版本，交付源码及可运行说明；如无法构建Windows exe如实说明。
