# AI职场沟通训练师｜项目成果展示

建议讲述 6–8 分钟，另留现场演示时间。使用用户提供的中国中车模板，保持 4:3 版式。案例和对话为虚构演示，不作为实际项目结论或实测模型效果。

## 01｜AI职场沟通训练师

**页面内容**

把下一次高压沟通，提前练一遍。
项目汇报 / 技术评审 / 客户沟通 / 国际协作

**讲述稿**

大家好，今天介绍的是 AI职场沟通训练师。很多工作难题，卡在关键的一次沟通：事实已经掌握，话却没有说到对方关心的点上。我们想做的，就是给重要沟通加一次低成本的预演。

## 02｜汇报前最怕的，往往是这一句。

**页面内容**

朱总：现在到底能不能交付？你需要我决定什么？
我：基本都差不多了，大家一直在加班……
判断说不清｜证据拿不出｜请求落不下

**讲述稿**

先请大家想象一个场景：周例会上，朱总问你能不能交付。你说大家很辛苦、项目差不多了，但对方还是继续追问。问题往往不在于态度，而在于判断、证据和请求没有对齐。这就是这个项目切入的真实场景。

## 03｜从准备到开口，形成一个完整闭环。

**页面内容**

选对象与场景 → 连续对话 → 六维复盘 → 画像与经验沉淀
4类场景：项目汇报、技术评审、客户沟通、国际协作。

**讲述稿**

整个流程可以用四步理解。先把人和事选清楚，再真正开口练。对话结束后，系统会把每一轮原话、评分依据和改进示范放在一起。练过的内容会逐步形成个人画像和可复用经验，让下一次练习有积累。

## 04｜选对象、带背景，开始一场有目标的练习。

**页面内容**

朱总：项目负责人。
围绕工作目标、关注点、语录和专业背景模拟追问。
可选场景、项目背景与追问强度，支持 OpenAI 兼容服务商。

**讲述稿**

这是目前可运行的实际界面。以演示对象朱总为例，他是一位技术背景的项目负责人，比较重视证据、风险边界和行动闭环。用户可以选场景、带入项目背景、调节追问强度。模型调用沿用已有 API 能力，支持 OpenAI 兼容服务商。截图仅展示产品界面，没有进行真实模型效果测试。

## 05｜同一个交付问题，两种回答。

**页面内容**

糟糕：基本都差不多了，大家最近一直在加班。周五交付应该没问题。
优秀：目前还不能承诺周五整机交付。常温验证已通过，高温验证尚未完成。我负责今天下班前补齐验证计划；请您确认台架优先级，再确定可交付范围。
关键：明确判断、已知事实、未知边界、具体请求。
本页为虚构演示。

**讲述稿**

这一页可以现场读两种回答。第一种听起来很积极，但领导仍然无法判断风险；第二种没有把话说满，却把判断、事实、未知项和请求说清楚了。演示重点是表达如何支持决策，不能把本页虚构的验证状态当成真实项目数据。

## 06｜一句应该没问题，接下来会发生什么？

**页面内容**

朱总继续追问：哪些验证已经关闭，哪些还没关闭？周五交付的具体范围是什么？
练习重点：先回答当前问题，再给证据、边界与下一步。
截图中的对话为虚构演示数据。

**讲述稿**

连续对话的价值在这里：一句差不多，并不会让讨论自然结束。系统会根据前面的表达继续追问，让问题暴露在练习中。我们希望使用者逐步养成一个习惯：先回答当前问题，再给必要的证据、边界和下一步，而不是堆积更多背景。截图内对话是为展示产品布局填入的虚构示例。

## 07｜找到最该改的一点，再说一遍。

**页面内容**

六维：结论清晰、证据具体、诉求对齐、边界与风险、下一步行动、理解与协作。
每轮总分与原话依据；逐轮点评与改进示范；原话三层解读；长期沟通画像。

**讲述稿**

复盘覆盖六个维度，而且评分必须有本轮原话依据。用户可以看每轮总分、具体点评和改进示范，也能看到对方原话的表面问题、核心关切和判断依据。评分是训练反馈，不是经验证的能力测量；更有价值的是找到下一轮能实际改动的一点。

## 08｜一份会议纪要，变成下一轮练习的底稿。

**页面内容**

会议纪要可提取：对象观察与语录、项目背景与行动项、可复用沟通经验。
先看原文依据，再核对人物和项目归属，最后勾选保存。
支持粘贴、TXT、Markdown、DOCX；入口已移至自由输入框上方。

**讲述稿**

很多沟通信息已经存在于真实会议纪要里。这个入口可以把它们整理成三类训练资料：对象画像和语录、项目背景和行动项、可复用经验。每项都有可展开的原文依据，人物和项目归属可以调整，核对后再保存。纪要记载不等于录音逐字稿，特征推测也不等于确定人格。

## 09｜可运行的原型，已经具备完整训练闭环。

**页面内容**

已实现：连续对话、六维复盘、双侧画像、经验库、会议纪要导入。
已验收：68项后端测试、真实Chromium流程、四主题、HTML/PDF导出。
支持本地启动和OpenAI兼容服务商。
待试点采集：真实提取质量、沟通改善幅度、准备时间与反馈。

**讲述稿**

目前已经完成可本地启动的原型和主要功能闭环，68项后端测试以及浏览器流程验证已经通过。这里需要把证据边界讲清楚：这些验证说明流程和协议可运行，没有证明沟通能力提升了某个百分比。真实提取质量、节省时间和应用效果，需要下一步通过脱敏试点收集。

## 10｜想改什么，直接说。

**页面内容**

朱总更重视风险边界，补到画像里。
把追问强度调为深入。
自然语言可新增对象、补充画像和语录、调整追问强度、收录经验。原表单保留。

**讲述稿**

用户不用每次都把所有字段填一遍。可以直接说朱总今天说了什么、自己观察到什么，或者希望把追问强度调高一点。系统整理后列出保存结果；不明确的对象会继续询问。原来的表单保留，适合做精细修改。

## 11｜越用，越贴近自己的工作场景。

**页面内容**

工作资料 → 连续对话 → 原话复盘 → 画像与经验 → 下一次练习。
旧训练保留快照，新观察和新经验用于后续练习。

**讲述稿**

这项应用的积累价值来自这个循环。工作资料让练习更贴近现实，连续对话暴露表达中的空缺，复盘把问题变成可执行的改法，再沉淀为画像和经验。历史训练保留当时的快照，避免后来的资料更新改写过去的评分依据。

## 12｜现场演示：从差不多走到明确下一步。

**页面内容**

1. 选朱总，带入脱敏背景。
2. 用糟糕回答试一次，观察追问。
3. 结束并复盘，查看依据和改进示范。
4. 换一种更清楚的回答，再练一次。

**讲述稿**

现场可以这样演示：先选朱总和项目汇报，输入那段差不多、一直加班的回答，看看对方会追问什么；然后结束并复盘，找到一个最需要改的点；最后换成更明确的回答再练。另可演示导入纪要和自由输入。建议提前准备脱敏样例及一份已保存的复盘，模型响应较慢时仍能讲清流程；所有示例数据明确标为虚构。
